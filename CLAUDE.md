# tree-sitter-rst

@AGENTS.md

A tree-sitter grammar for reStructuredText, forked from
[stsewd/tree-sitter-rst](https://github.com/stsewd/tree-sitter-rst) (MIT).
The goal is a parse tree that reads a document the way docutils does, so
that formatters and scanners built on it (Moldy's reStructuredText
formatter first) can trust it on real documentation.

## Layout

| Path | What it is |
| --- | --- |
| `grammar.js` | The grammar rules. |
| `src/scanner.c`, `src/tree_sitter_rst/` | The hand-written external scanner: indentation, blank lines, list and option markers, explicit markup, inline markup. Most of the grammar's behavior lives here. |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | Generated by `tree-sitter generate`. Never edit them by hand; regenerate and commit them with the change to `grammar.js`. |
| `test/corpus/*.txt` | Grammar tests: input and expected tree (`tree-sitter test`). |
| `bindings/` | Language bindings (C, Go, Node, Python, Rust, Swift), as generated upstream. |
| `queries/` | Highlighting and injection queries. |
| `scripts/` | Repository checks: commit-message policy and the agent command guard, with their tests. |
| `conf/` | Gate configuration: the knots baseline and the aurora-lint manifest. |

## How the grammar reads a document

Follow docutils, not intuition: the reference is the
[reStructuredText specification](https://docutils.sourceforge.io/docs/ref/rst/restructuredtext.html)
and docutils' own parser (`docutils/parsers/rst/states.py`). When the two
seem to disagree, docutils' behavior wins, because that is what a
document's author sees rendered. Indentation decides structure: a block's
indent is set by its lines as docutils sets it (for example, the body of
explicit markup by its least indented line), not by the first line alone.

Error recovery matters as much as success. A document docutils accepts
should parse without `ERROR` or `MISSING` nodes, and also without a token
the parser inserted silently, which `--dump-tree` does not show. A
document docutils rejects may produce errors.

## Changing the grammar

1. Reproduce the problem as a small document and parse it
   (`tree-sitter parse file.rst`). Compare with docutils' reading
   (`python -m docutils --strict file.rst`, or its pseudo-XML output).
2. Add a test to the matching `test/corpus/*.txt` file. It must fail
   before the fix and pass after it.
3. Fix `grammar.js` or the scanner. After a `grammar.js` change, run
   `invoke generate` and commit the generated files with it.
4. Run `invoke test`, then check real documents: parse a corpus of real
   reStructuredText (Python, Linux and Zephyr documentation, and our own
   projects' docs), and compare error counts and trees before and after.
   A fix that reads one shape right can read a neighboring shape wrong; a
   consumer's own checks (Moldy refusing a file it cannot confirm) show
   that too.

Keep one logical change per commit.

## Running and verification

```sh
pip install invoke pre-commit
pre-commit install          # installs the pre-commit and commit-msg hooks
invoke generate             # regenerate src/ from grammar.js
invoke build                # generate check + Rust binding build
invoke test                 # tree-sitter test + cargo test
invoke check                # every pre-commit hook on all files
```

The tasks run the tree-sitter CLI named by `TREE_SITTER` (default
`tree-sitter` on `PATH`), which must be the version in `package.json`'s
`tree-sitter-cli`; a different version generates a different `parser.c`.

The hand-written C (`src/scanner.c`, `src/tree_sitter_rst/`) is formatted
by moldy and gated by knots and aurora-lint, as in our other repositories.
knots compares each function with `conf/knots_baseline.json`: a new
function must meet the thresholds, and an existing one may not get worse.
aurora-lint's existing findings are recorded, unreviewed, in
`conf/aurora-lint-suppress.toml`; a new finding fails the check, and a
recorded one lapses when its line changes. Fix or review a recorded finding
when the code around it changes, and remove its entry once it is fixed.
`conf/aurora-lint-rules.toml` holds the rules and what the scanner is built
for (environment, allocators, scope). Generated C is not formatted or gated.

## Upstream

Keep the fork's changes easy to offer upstream: one fix per commit, each
with its test. Sending anything upstream needs the maintainer's approval
(AGENTS.md).
